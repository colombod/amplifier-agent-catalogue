# Fixes Applied: 2026-02-07

## Summary

Fixed multiple issues preventing the improvement workflow from displaying tool activity correctly in the UI.

## Problems Fixed

### 1. Tool Protocol Mismatch

**Problem**: Orchestrator expected `input_schema` property but tools only had `get_schema()` method.

**Symptoms**: Tools loaded but couldn't be called by loop-streaming orchestrator.

**Fix**: Added `@property input_schema` to all 8 tools that returns `self.get_schema()`.

**Files**:
- `src/agent_catalogue/tools/search.py` - SearchSimilarTool
- `src/agent_catalogue/tools/storage.py` - GetAgentContentTool and others
- `src/agent_catalogue/tools/analysis.py` - EmbedTextTool

**Verification**: Tools now mount successfully and orchestrator can invoke them.

---

### 2. Double Evaluation Bug

**Problem**: Clicking "Improve, Then Store" ran the evaluator agent twice:
1. Once in Step 4 to show quality grade
2. Again in `/api/stream/improve` endpoint (wasteful, ~15 seconds)

**Symptoms**: Improvement took 30+ seconds instead of 15 seconds.

**Fix**: 
- Backend accepts optional `evaluation` parameter in `/api/stream/improve`
- Frontend passes `evaluationData` from Step 4
- Evaluator only runs if evaluation not provided

**Files**:
- `src/agent_catalogue/api/routes.py:1549-1622` - Check for `provided_evaluation`
- `src/agent_catalogue/web/templates/upload.html:1641` - Pass evaluation in request

**Log evidence**: 
```
02:13:14 Using provided evaluation from Step 4 (skipping evaluator)
```

---

### 3. SSE Bridge Field Name Bug

**Problem**: SSE bridge looked for `data["tool_result"]` but orchestrator sends `data["result"]`.

**Symptoms**: UI showed "0 chars" for all tool outputs despite tools succeeding.

**Root cause**: 
```python
# Orchestrator emits
hooks.emit("tool:post", {"result": ToolResult(...)})

# Bridge was looking for
tool_result = data.get("tool_result", {})  # Always empty!
```

**Fix**: Changed to `data.get("result", {})`

**File**: `src/agent_catalogue/sse_bridge.py:189`

---

### 4. Success Detection Bug

**Problem**: UI showed "✗ failed" for successful tools.

**Symptoms**: All tools showed red ✗ despite succeeding in reality.

**Root cause**: ToolResult includes `error: None` key even when successful. Code checked `"error" in tool_result` (True) → assumed failure.

**Fix**: Check if error has **content**, not just if key exists:
```python
# OLD
success = tool_result.get("success", True) if "error" not in tool_result else False

# NEW  
has_error = bool(tool_result.get("error"))  # None → False
success = tool_result.get("success", True) if not has_error else False
```

**File**: `src/agent_catalogue/sse_bridge.py:203-207`

---

### 5. Uninformative Output Summaries

**Problem**: UI showed "0 chars" for all tool results (not helpful).

**Fix**: Pattern-match on output structure to generate informative summaries:

**search_similar**:
- 0 results → "no results"
- 1 result → 'found "Agent Name"'
- N results → "found N agents"

**get_agent_content**:
- '"Agent Name" (2387 chars)'

**File**: `src/agent_catalogue/sse_bridge.py:199-242`

---

**Fix**: Added file-based logging to `/tmp/agent-catalogue-debug.log` with:

**Files**:
